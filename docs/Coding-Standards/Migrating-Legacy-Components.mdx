# Coding standards: Migrating Legacy Components

This guide covers moving a component out of `src/app/legacy` into `src/app/components`.

> **Target state:** migrated components use **SCSS Modules + CSS custom properties**
> (`ThemeProviderSCSSModules`), TypeScript, and co-located tests.
> Do **not** migrate to Emotion. Emotion (`styled`, the `css` prop, `index.styles.ts`) is
> itself being removed — converting a legacy component to Emotion creates work that has to
> be redone. Go straight from `styled` to `index.module.scss`.

See `.github/instructions/styling-standards.instructions.md` and `Styles.mdx` for the full
styling rules, and `src/app/components/Example` for the canonical reference implementation.

## Before you start: migrate the whole cluster

Legacy modules are heavily interlinked, and the aliases `#components`, `#containers` and
`#psammead` all resolve **into `src/app/legacy`**. A component that looks standalone usually
pulls in several other legacy modules transitively.

Before opening a PR:

1. Map the component's transitive legacy dependencies, not just its direct imports.
2. Migrate **leaf dependencies first**, bottom-up. Shared leaves such as `gel-foundations`
   are pulled in by most clusters.
3. Where several entry points share the same interior modules, migrate them as a single
   unit rather than repeating the same interior work in multiple PRs.
4. Watch for cycles. `Header` ↔ `Brand` ↔ `Footer` are mutually dependent and cannot be
   split across PRs.

Do not leave a migrated copy alongside the legacy original. Update all importers and delete
the legacy module in the same PR.

## Props / Typing

### Do not define `children` as an interface prop

React provides helpers that accept `children` with the appropriate type without declaring it.

#### Before

```tsx
interface MyComponentProps {
  children: React.Node;
  prop1: string;
}

const MyComponent = ({ prop1, children }: MyComponentProps) => (
  <TheComponent prop1={prop1}>{children}</TheComponent>
);
```

#### After

```tsx
import { PropsWithChildren } from 'react';

interface MyComponentProps {
  prop1: string;
}

const MyComponent = ({
  prop1,
  children,
}: PropsWithChildren<MyComponentProps>) => (
  <TheComponent prop1={prop1}>{children}</TheComponent>
);
```

### Where appropriate, add new types/interfaces to a `types.ts` file next to the component

This keeps types in a single location that can be imported where required. Do this when the
type is needed in a shared (but not global) location, or is used by other components.

**(types.ts)**

```ts
export interface MyComponentProps {
  prop1: string;
}
```

**(index.tsx)**

```tsx
import { MyComponentProps } from './types';

const MyComponent = ({ prop1 }: MyComponentProps) => {
  // ...
};
```

### ⚠️ When not to declare types/interfaces in a separate `types.ts` file

Keep the declaration next to the component when it is not used anywhere else.

## Styling

### Replace `styled` with an `index.module.scss` file

Import the shared design tokens with `@use '@scss/themeTokens' as theme;` and apply classes
via `className`. Never hard-code colours, spacings, font values or breakpoints.

#### Before

**(index.jsx)**

```jsx
const StyledContainer = styled.div`
  color: ${props => props.theme.palette.BLACK};
  text-align: center;
  padding: ${GEL_SPACING_DBL};
`;
```

#### After

**(index.module.scss)**

```scss
@use '@scss/themeTokens' as theme;

.container {
  color: theme.$palette-black;
  text-align: center;
  padding: theme.$spacings-double;
}
```

**(index.tsx)**

```tsx
import styles from './index.module.scss';

const MyComponent = () => <div className={styles.container}>...</div>;
```

### Migrating media queries

Media query variables are strings, so they are used with interpolation:
`@media #{theme.$mediaQueries-group-2-min-width} { ... }`.

Prefer a mobile-first approach: write base styles for mobile, then layer on `min-width`
queries for larger viewports.

#### Before

```jsx
const StyledLink = styled.a`
  @media (min-width: ${GEL_GROUP_2_SCREEN_WIDTH_MIN}) {
    ...cssForGroup
  }
`;
```

#### After

```scss
@use '@scss/themeTokens' as theme;

.link {
  @media #{theme.$mediaQueries-group-2-min-width} {
    /* cssForGroup */
  }
}
```

### Media query / breakpoint mappings

| Before                                             | After                                        |
| -------------------------------------------------- | -------------------------------------------- |
| **Min widths**                                      |                                              |
| `@media (min-width: 240px) {`                       | `theme.$mediaQueries-group-1-min-width`      |
| `@media (min-width: 400px) {`                       | `theme.$mediaQueries-group-2-min-width`      |
| `@media (min-width: 600px) {`                       | `theme.$mediaQueries-group-3-min-width`      |
| `@media (min-width: 1008px) {`                      | `theme.$mediaQueries-group-4-min-width`      |
| `@media (min-width: 1280px) {`                      | `theme.$mediaQueries-group-5-min-width`      |
| **Max widths**                                      |                                              |
| `@media (max-width: 239px) {`                       | `theme.$mediaQueries-group-0-max-width`      |
| `@media (max-width: 399px) {`                       | `theme.$mediaQueries-group-1-max-width`      |
| `@media (max-width: 599px) {`                       | `theme.$mediaQueries-group-2-max-width`      |
| `@media (max-width: 1007px) {`                      | `theme.$mediaQueries-group-3-max-width`      |
| `@media (max-width: 1279px) {`                      | `theme.$mediaQueries-group-4-max-width`      |
| **Forced colours / high contrast**                  |                                              |
| `@media screen and (forced-colors: active)`         | `theme.$mediaQueries-forced-colours`         |

There are no combined "only" / "group 1 and 2" variables. Compose the min and max variables
instead:

```scss
@media #{theme.$mediaQueries-group-1-min-width} and #{theme.$mediaQueries-group-2-max-width} {
  /* previously GROUP_1_AND_GROUP_2 */
}
```

### Migrating GEL spacing

| Pixels | GEL spacing              | New SCSS token               |
| ------ | ------------------------ | ---------------------------- |
| 4px    | `GEL_SPACING_HLF`        | `theme.$spacings-half`       |
| 8px    | `GEL_SPACING`            | `theme.$spacings-full`       |
| 16px   | `GEL_SPACING_DBL`        | `theme.$spacings-double`     |
| 24px   | `GEL_SPACING_TRPL`       | `theme.$spacings-triple`     |
| 32px   | `GEL_SPACING_QUAD`       | `theme.$spacings-quadruple`  |
| 40px   | `GEL_SPACING_QUIN`       | `theme.$spacings-quintuple`  |
| 48px   | `GEL_SPACING_SEXT`       | `theme.$spacings-sextuple`   |
| 8px    | `GEL_MARGIN_BELOW_400PX` | `theme.$spacings-margin-below-400px` |
| 16px   | `GEL_MARGIN_ABOVE_400PX` | `theme.$spacings-margin-above-400px` |
| 8px    | `GEL_GUTTER_BELOW_600PX` | `theme.$spacings-gutter-below-600px` |
| 16px   | `GEL_GUTTER_ABOVE_600PX` | `theme.$spacings-gutter-above-600px` |

`GEL_SPACING_HLF_TRPL` (12px) and `GEL_SPACING_SEPT` (56px) have no token. Use
`theme.pixelsToRem-px-to-rem(12)` / `theme.pixelsToRem-px-to-rem(56)`.

### Values driven by props

With `styled` it was possible to vary CSS from any prop. With SCSS Modules, keep the
conditional logic in the component and select between classes.

#### Before

```jsx
const Timestamp = styled.time`
  color: ${props =>
    props.isAmp ? props.theme.palette.BLACK : props.theme.palette.GREY_3};
`;
```

#### After

**(index.module.scss)**

```scss
@use '@scss/themeTokens' as theme;

.timestamp {
  color: theme.$palette-grey-6;
}

.timestampAmp {
  color: theme.$palette-black;
}
```

**(index.tsx)**

```tsx
<time className={isAmp ? styles.timestampAmp : styles.timestamp}>
```

For a genuinely per-instance numeric value, set a single CSS custom property inline and
reference it from the stylesheet, rather than generating dynamic class names:

```tsx
<ul className={styles.list} style={{ '--row-count': rowCount } as CSSProperties}>
```

```scss
.list {
  grid-template-rows: repeat(var(--row-count), auto);
}
```

### Dark UI and directionality

- Handle dark UI with `:global([data-is-dark-ui='true']) &` inside the `.module.scss`,
  rather than branching in TypeScript.
- Use logical properties (`padding-inline-start`, `margin-inline-end`) for RTL support.
  Do not branch `className` on `dir`, and do not use `[dir='rtl']` selectors.

### Grid

`psammead-grid` must not be used in migrated components. CSS Grid is permitted for page
layout only, because Opera Mini falls back to inline layout. Scope any unavoidable Opera
Mini override with `:global(.is-opera-mini) &`.

## Tests

- Use `src/app/components/react-testing-library-with-providers` rather than
  `@testing-library/react` directly, so context providers are applied.
- **Delete legacy snapshot files.** Snapshots assert on markup and will fail on every
  styling change without describing intended behaviour. Replace them with behavioural
  assertions.
- Legacy components often branch on `isAmp`. Verify the canonical, AMP and Lite render
  paths.
- Be service-aware: check per-service branching (variants, translations, directionality)
  and test at least one RTL service (for example `arabic`) alongside a Latin-script one.

## General Standards

### Use `@ts-expect-error` instead of `@ts-ignore`

`@ts-expect-error` requires a description, and the compiler will flag it once the underlying
error is fixed, prompting removal. `@ts-ignore` silently rots.

#### Before

```ts
// @ts-ignore
broken.typescript.syntax;
```

#### After

```ts
// @ts-expect-error ignoring broken TS syntax until ticket 12345 is merged
broken.typescript.syntax;
```
